# Devnet deployment gate — receipt-settlement (J-4)

> **Status: PREPARED, NOT RUN.** Nothing has been deployed to devnet or
> mainnet. `scripts/deploy-devnet.sh` exists so a deployment, once approved,
> is reproducible and leaves evidence. Mainnet is out of scope.

## The deployed program will be UPGRADEABLE

The script deploys with the BPF **upgradeable** loader
(`BPFLoaderUpgradeab1e11111111111111111111111`) and sets the upgrade
authority to the deployer key. **Whoever holds that key can replace the
program's code at any time**, including the settlement rules in
[SETTLEMENT-SPEC.md](SETTLEMENT-SPEC.md). Anyone relying on the devnet program
must check `solana program show <PROGRAM_ID> --url devnet` for the current
authority and last deploy slot. Making it immutable
(`solana program set-upgrade-authority --final`) is a separate, irreversible
decision that is not part of this gate.

## Gate (all must hold before running)

1. Explicit approval to deploy to devnet, naming the commit.
2. `DEPLOY_COMMIT` is a pushed commit whose LiteSVM and local-validator suites
   passed (evidence under `evidence/anchor-receipt-settlement/<commit>/`).
3. Program-id keypair decided. `declare_id!` in `lib.rs` is
   `8JMkxGfiEfXJ3xJgt9Dh2bzdp6ozL6WQ5E534WfLwHfT`, generated by `anchor init`
   on the build box and never committed. Either use that keypair (copy it out
   of `onchain/target/deploy/` to a path outside any repository), or generate
   a new one and land `anchor keys sync` as a reviewed commit first. The script
   aborts if the keypair's pubkey differs from `declare_id!`.
4. A devnet deployer keypair outside the repository, funded with devnet SOL
   (faucet). Program-data rent for a ~275 KB program is roughly 1.9 SOL plus
   buffer/transaction fees; have ≥ 4 devnet SOL. **No keypair is ever
   committed.**
5. Toolchain on `PATH`: Anchor 1.2.1, Agave/solana CLI 4.3.0 (the script
   checks both), git, python3, readelf, sha256sum.
6. Devnet RPC reachable. The script checks the genesis hash
   (`EtWTRABZaYq6iMfeYKouRu166VU2xqa1wcaWoxPkrZBG`) and that the SBPF v3
   feature `5cC3foj77CWun58pC51ebHFUWavHWKarWyR5UUik7dnC` is active, because
   the artifact is SBPF v3 (ELF flags 0x3).

## Run

```bash
EDGEORE_DEPLOY_CONFIRM=devnet \
DEPLOY_COMMIT=<40-hex sha> \
DEPLOYER_KEYPAIR=$HOME/keys/devnet-deployer.json \
PROGRAM_KEYPAIR=$HOME/keys/receipt_settlement-program.json \
scripts/deploy-devnet.sh
```

Optional: `RPC_URL` (default `https://api.devnet.solana.com`; mainnet-looking
URLs are refused), `REPO_URL`, `OUT_DIR`.

## What the script does

| Step | Action | Recorded in `deploy-record.txt` |
|---|---|---|
| 0 | preflight: tool versions, devnet genesis hash, SBPF v3 feature, balances | rpc_url, genesis_hash, deployer, balance, program id |
| 1 | `git clone --no-local` into a temp dir, detached checkout of `DEPLOY_COMMIT`, clean tree, keypairs outside any repo, `declare_id!` == program keypair | commit, declare_id |
| 2 | `anchor build` in the clean clone | built_so_sha256, bytes, ELF flags |
| 3 | `solana program deploy --program-id … --upgrade-authority <deployer>` | deploy_signature |
| 4 | `solana program show --output json` | programId, owner (must be upgradeable loader), programdataAddress, **authority**, **lastDeploySlot**, dataLen |
| 5 | `solana program dump` | dumped bytes + sha256 |
| 6 | sha256 of the dump's first `len(.so)` bytes == built sha256, and any trailing bytes all zero | sha256_match PASS/FAIL (non-zero exit on FAIL) |

Evidence lands in `OUT_DIR` (`deploy-devnet.log`, `deploy-record.txt`,
`anchor-build.log`, `built.so`, `dumped.so`, JSON outputs). Copy it to
`evidence/anchor-receipt-settlement/<commit>/devnet-deploy/` in a follow-up
commit. The built sha256 in a clean clone may differ from a local
`anchor build` on another machine (non-verifiable build); the comparison that
matters is built-in-clone vs. dumped-from-chain.
